# 后端当前问题与上线前修改建议

> 文档日期：2026-08-21

目前后端已经可以完成基本的订阅、扫描和通知流程，但在正式开放公网前，建议优先处理以下问题。

## 1. API 鉴权尚未真正接入

目前登录验证成功后虽然会返回 Bearer Token，但订阅、通知渠道、扫描等接口并没有校验 Token，`user_id` 仍由前端直接传入。

建议：

- 为 `/api/v1/*` 用户接口统一加入 Bearer Token 鉴权。
- 后端从 Token 中获取当前用户 ID，不信任请求参数中的 `user_id`。
- `/api/v1/tasks/scan`、`/api/v1/admin/health` 等管理接口限制为管理员或仅内部访问。

**优先级：最高**

## 2. 邮箱验证码目前没有真正发送

当前验证码只是：

- 写入数据库；
- 打印到后端日志；
- 开发模式下通过 `dev_code` 返回。

还没有通过 SMTP 发到用户的浙大邮箱。

建议：

- 接入现有 SMTP 配置发送验证码邮件。
- 生产环境设置 `AUTH_DEV_PRINT_CODE=false`。
- 删除日志中直接打印验证码的行为。

**优先级：最高**

## 3. Token 签名配置需要统一

`.env.example` 提供了：

```env
JWT_SECRET=change-me-in-production
```

但实际 Token 签名目前使用的是 `AUTH_HASH_SALT`，且存在固定默认值。

建议统一使用一个强随机生产 Secret，并避免代码中存在可用的默认 Secret。

**优先级：高**

## 4. CC98 请求失败会静默降级到 Mock 数据

当前真实 CC98 请求异常时，Watch 会自动返回 Mock 帖子，因此可能出现：

> RVPN / CC98 已经失效，但定时任务看起来仍然正常。

建议：

- `WATCH_FORCE_MOCK_TOPICS` 只用于开发环境。
- 生产环境真实 CC98 请求失败时直接记录失败状态，不要自动回退 Mock。
- 在 health / worker 状态中明确暴露 CC98 请求异常。

**优先级：高**

## 5. 公网部署相关

当前如果直接开放 API 到公网，还建议：

- 正式环境不要使用 `CORS_ORIGINS=*`，改成实际前端来源。
- Swagger `/docs` 是否公开可以视情况关闭或限制。
- 后端建议只监听 `127.0.0.1:8000`，正式上线通过 Nginx + HTTPS 对外提供服务。
